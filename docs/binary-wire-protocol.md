# Binary application protocol (0.5.0)

This is a breaking, unpublished migration. Do not deploy it piecemeal on the old
Peach network. Old chain roots are rejected, never silently relabelled or erased.
The public genesis contract artifacts have been re-addressed for the new encoding;
their JavaScript, owner identity and allocations are preserved. No identity is
generated by this migration. Back up existing roots and use separate test roots.

## Application boundaries

- Message schemas: codec prefix followed by a versioned binary tuple in declared
  schema order. Validator submessages use canonical length-delimited byte frames.
- Typed values: `LFC`, byte version `1`, then a type tag. Undefined, null, booleans,
  finite IEEE-754 numbers, signed 256-bit BigInts, UTF-8 strings, byte arrays,
  arrays and sorted-key plain maps have distinct representations. BigInts are
  binary magnitudes, not decimal strings or `$bigint` maps. Byte fields are not
  JSON arrays or base64 strings. Byte fields supplied as contract source text are
  converted to UTF-8 locally before encoding.
- Worker IPC: domain `worker`. Parent and child exchange only `Uint8Array`;
  Node uses advanced IPC serialization to preserve the byte view. State seeds
  and loaded blocks are typed values, not nested JSON strings.
- HTTP RPC: `application/octet-stream`, domain `rpc`. Parameterized calls use
  POST with a binary map. Parameterless GET reads may return binary responses.
  Query-string/JSON payloads are rejected. Errors use the same binary envelope.
- WebSocket RPC: subprotocol `<networkVersion>.lfc-binary-v1`; binary frames in
  domains `rpc-request` / `rpc-response`. Text frames are closed with 1003,
  malformed envelopes with 1002. Requests have bounded pending counts/timeouts.
- Manager, public explorer and faucet use binary HTTP. Explorer content and
  uploaded contracts are direct byte fields. Chat packets use domain `chat`.
  Peer response and tip decoders no longer guess JSON, object or legacy hash forms.

Decoders reject trailing/truncated data, unknown versions/tags, non-canonical
varints, unordered/duplicate keys, invalid UTF-8 and oversized/deep collections.
Encoders reject cycles, accessors, sparse arrays, non-finite numbers and custom
object prototypes. Limits apply before unbounded allocation where possible.

## Rollout and remaining upstream work

`npm run test:wire` builds dependencies and runs workspace tests before the live
multi-process fixtures. Do not run builds concurrently with those fixtures:
worker/chain builds replace generated modules that newly spawned processes load.

Publish the versioned workspace packages in dependency order before consumers:
binary/addresses, messages, lib, workers, chain, endpoints/endpoint-clients, launch
and faucet. Rebuild the browser node and manager together. No packages are
published by tests or by this change.

The application migration is **not** proof that the whole networking stack is
JSON-free. The currently pinned external `@netpeer/swarm` discovery/signaling
server and `socket-request-*` control protocol still use JSON. External peernet
archive/replication and capability paths also need an upstream migration. These
repositories and services must be upgraded together, with mixed-version rejection
and cross-process tests, before claiming an entirely binary network. The chain
installs binary peer message schemas before discovery; this is not a replacement
for that upstream work. Chat only delegates archive handling to providers explicitly
advertising `binaryArchiveVersion === 1`; otherwise it uses its local binary path.

The editor now requires a binary `/bundle` POST service returning `{ code }` in
the binary `rpc` domain. The external deployer must be upgraded to this API; it
does not silently retry JSON against the old service.

JSON that describes local configuration, encrypted backups, checkpoint journals,
test diagnostics or canonical signature inputs is not an application wire format.
Static HTML/JavaScript assets and standard HTTP/WebRTC transport metadata are
separate from application payloads.
